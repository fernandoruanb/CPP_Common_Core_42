## About the CPP Modules

Here we are facing the full set of **10 C++ modules** from École 42.

These projects were revisited, reviewed, and refined, including corrections for issues and small bugs that could have persisted from my **common core** phase.

Taken together, the CPP modules form one of the most valuable learning tracks in the 42 curriculum.

They are extremely well designed to take someone from an almost absolute beginning in C++ to a point where that person can build real confidence with:

- syntax and structure
- object-oriented programming
- memory management
- references and pointers
- operator overloading
- inheritance and polymorphism
- abstract classes and interfaces
- exception handling
- templates
- STL containers and algorithms

This is what makes the CPP path so powerful.

It is not just a language change.

It is a gradual transformation in the way we think about software design.

---

## Why This Journey Matters

Coming from C, the contrast is striking.

At 42, we spend a long time building discipline through a language that gives us very little for free.

That matters.

Because when we finally reach C++, we are not arriving as beginners in programming logic.
We are arriving after already suffering through:

- manual implementation
- strict control over memory
- lower-level reasoning
- building many tools from scratch
- solving problems with fewer abstractions

And that changes everything.

When C++ begins to open new doors, the effect is not simply “this language has more features.”

The effect is more like:

> now I understand why these abstractions are powerful.

That is part of what makes the C++ modules so rewarding after the common core.

---

## What The Modules Teach

Across the ten modules, we progressively learn how to work with many of the most important pillars of C++.

Among them:

- native C++ language features
- memory allocation and object lifetime
- pointers and references
- classes, objects, and methods
- canonical orthodox form
- operator overloading
- inheritance
- polymorphism
- abstract classes
- custom exceptions
- templates
- containers such as `vector`, `map`, `list`, and `deque`
- iterator-based design
- cleaner and more expressive implementations than what we were used to in C

This journey also teaches something deeper:

C++ is not only about adding features on top of C.

It is about gaining new ways to model, organize, and express solutions.

That is why, along the path, we can suddenly do things that would feel disproportionately hard in pure C.

For example:

- creating a `sed`-like replacer in just a few lines
- avoiding repetitive chains of `if` with cleaner dispatch logic
- creating our own operators
- building generic structures with templates
- even giving iterator support to something unexpected, such as a mutant stack

This is where the language starts to feel truly rich.

## From C to C++

One of the most interesting ways to understand this transition is through problem solving.

A good example for me was the **“Laptops”** problem from Codeforces: https://codeforces.com/problemset/problem/456/A.

I had tried to solve it in C, building things from the ground up, and it was much harder.  
I could get through several tests, but performance and implementation complexity made the whole process much more painful.

Then, when I approached the same problem using C++, the experience changed dramatically.

The core idea was already in my head.

But now, with better tools and a more expressive language, the implementation became much easier and much more natural.

That contrast says a lot.

It shows how much we suffer and sharpen ourselves when starting from the hardest side — pure C — and then how impressed we become when reaching C++ and seeing how much more organized, elegant, and practical many solutions can be.

That is one of the big gifts of the 42 path.

It makes us earn the abstraction before receiving it.

## What Comes Next

These modules are not the end of the road.

They are preparation.

They build the confidence and technical maturity needed to approach much more complex projects in the future, including systems where clean architecture and strong abstraction choices matter far more.

By the time someone finishes this path seriously, they are no longer just “trying to use C++.”

They are starting to understand how to **shape solutions with C++**.

And that opens the door to much more ambitious implementations.

This is why the CPP modules are so valuable:
they do not just teach syntax.

They train mindset.

They train design.

They train confidence.

And they offer a glimpse of what is still to come.

---

## Final Note

The C++ modules at École 42 are much more than a language sequence.

They are a transformation arc.

They take us from manual and rigid construction toward expressive, scalable, and elegant software design.

After beginning in the harsh world of C, arriving here feels almost shocking in the best possible way.

You start by being impressed that something difficult can now be solved cleanly.

Then, little by little, you realize something even more important:

you are not just learning a new language.

You are learning a new level of software thinking.

And this introduction is only a small taste of what comes next.
